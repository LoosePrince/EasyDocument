# 常见问题

## 内容与构建

**改了文档，线上没变？**

内容分支的提交不会自动触发部署。到 `/admin` → **构建部署** → **立即重建**，或：

```bash
gh workflow run deploy.yml --ref main
```

**本地 `npm run dev` 读不到内容？**

优先读 `.data` 目录。没有的话执行：

```bash
git worktree add .data origin/data
```

或者设置环境变量 `EASYDOCUMENT_DATA_DIR` 指向任意内容目录。两者都没有时会回退到从 GitHub 远程读取。

**构建时文档数量为 0？**

- 检查内容分支里是否只有 `config.js`，没有版本目录
- 检查版本目录名是否与 `document.default_branch` 一致
- 检查文件扩展名是否在 `supported_extensions` 内

## 导航与链接

**侧栏里某个目录点不了？**

该目录没有索引页。放入一个 `README.md`（或 `index.md`）后重新构建即可。

这是刻意设计：宁可不可点，也不给出一个通向 404 的入口。

**顶部导航项变灰了？**

配置里写的路径没有对应的真实页面。补上文档，或把 `nav_links[].url` 改成存在的路径。

**文档间链接点了 404？**

- 相对路径要写全，包括扩展名：`[x](./另一篇.md)`
- 大小写敏感（构建与部署环境是 Linux）
- 跨目录用 `../`

**旧版的 `main/#路径` 链接还能用吗？**

配置中的导航、首页按钮等站内路径会自动转换。但如果链接写在文档正文里，请改成相对路径或 `/docs/...` 形式。

## 编辑与发布

**「保存」和「提交」到底差在哪？**

- 保存 = 写入本浏览器草稿，不联网
- 提交 = 推送全部草稿到 GitHub 内容分支
- 重建 = 触发 Actions 让线上更新

详见 [编辑与发布](../编辑与发布/README.md)。

**草稿会不会丢？**

保存在 `localStorage`，刷新、切页、关闭浏览器都不丢。清除站点数据或换浏览器会丢。

**提交提示冲突？**

同一文件在远端已被他人修改。刷新页面重新编辑后提交，或在 GitHub 上手动处理。

**Token 需要什么权限？**

fine-grained PAT：仅本仓库，`Contents: Read and write` + `Actions: Read and write`。

**能只提交部分草稿吗？**

目前是「全部草稿一起提交」。想排除某条，在草稿清单里点 × 放弃它。

## 显示问题

**数学公式显示成两遍？**

确认用的是当前版本（KaTeX 样式已内置）。若仍是两遍，检查是否自定义了 CSS。

**代码块没有高亮？**

- 代码块要写语言名
- `extensions.highlight` 是否为 true
- 语言是否在 shiki 支持范围内（浏览器端按需加载）

**Mermaid 没渲染？**

- `extensions.mermaid` 是否为 true
- 图表语法是否正确
- 构建产物里的 Mermaid 是客户端渲染，首屏短暂显示源码属正常

**暗色模式不跟随系统？**

手动选择过主题会覆盖系统偏好。清除 `localStorage["easydocument:theme"]` 后恢复跟随。

## 部署

**Actions 构建失败？**

常见原因：

| 日志关键字 | 原因 |
| --- | --- |
| `easydocument.json` | 指针文件缺失或格式错误 |
| `worktree add` | 内容分支不存在 |
| `tsc` | 类型错误（本地先跑 `npm run typecheck`） |
| `Prerender` | 某篇文档渲染报错，按提示路径定位 |

**Pages 显示 404？**

- 确认 Settings → Pages 的 Source 是 **GitHub Actions**
- 确认自定义域名/子路径与 `base_url` 一致

**`/admin` 打不开？**

控制台是预渲染页面，GitHub Pages 上没有 SPA 回退。如果部署环境缺少 `admin/index.html`，检查构建产物是否包含它。
