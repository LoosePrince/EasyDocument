# 编辑与发布

这一章把「保存」「提交」「重建」三个动作讲清楚——它们不是同一件事。

## 一张图看懂

```text
 编辑正文
    │
    ├─ 保存修改 ──▶ 本地草稿（localStorage）
    │                 │  可切页面、刷新、关闭浏览器，草稿都在
    │                 │
    │                 ├─ 一键提交 ──▶ 内容分支的 GitHub 提交
    │                 │                  │
    │                 │                  └─ 重建站点 ──▶ GitHub Actions ──▶ 线上更新
    │                 │
    │                 └─ 放弃 ──▶ 草稿丢弃，内容回到线上版本
```

| 动作 | 位置 | 是否联网 | 结果 |
| --- | --- | --- | --- |
| **保存修改** | 编辑区工具条 | 否 | 写入本浏览器草稿，可从列表查看/统计 |
| **一键提交** | 顶部提交栏 | 是（需 PAT） | 把全部草稿推送到内容分支 |
| **重建站点** | 控制台 → 构建部署 | 是（需 PAT） | 触发 Actions，让线上生效 |

> [IMPORTANT] 只保存不提交：改动只在你的浏览器里。只提交不重建：内容已在仓库，但线上仍是旧版本。

## 进入编辑

三种入口，效果相同：

1. 文档页右上角 **编辑此页**
2. 控制台右上角 **进入编辑模式**
3. 键盘 <kbd>E</kbd>（焦点不在输入框时）

进入编辑模式后，顶栏下方出现**提交栏**，侧栏切换为可管理状态。

## 编辑区

正文区域就地变成编辑器，支持三种模式：

| 模式 | 布局 | 适合 |
| --- | --- | --- |
| **所见即所得** | 直接编辑渲染结果本身 | 改文案、调结构，不碰语法 |
| 分栏 | 左源码、右预览，可同步滚动 | 边写边看、调整排版 |
| 预览 | 占满宽度，显示渲染结果 | 检查最终效果、阅读长文 |

**所见即所得**是 v2.0.1 的默认模式：标题、列表、表格、提示框都按发布样式显示，
直接在页面上改字、改层级即可。工具条提供标题、加粗、斜体、删除线、行内代码、
列表、引用、链接、提示框、表格、分隔线、撤销。

> [NOTE] 所见即所得模式下每次修改都会即时转回 Markdown 写进草稿，
> 切到「分栏」能看到对应的源码；两种模式可以随时来回切换，内容不会丢。

预览与构建期使用**同一套渲染管线**，所以编辑时看到的就是发布后的样子，包括：

- 提示框、表格、代码高亮与行号
- KaTeX 数学公式
- Mermaid 图表
- 标题锚点与相对链接改写

### 源码区细节

- 行号栏与文本同步滚动
- <kbd>Tab</kbd> 插入两个空格
- 回车自动续接列表标记（`-`、`1.`）
- <kbd>Ctrl</kbd>/<kbd>⌘</kbd> + <kbd>S</kbd> 保存

### 工具条按钮

| 按钮 | 作用 |
| --- | --- |
| 模式切换 | 所见即所得 / 分栏 / 预览 |
| 标题输入框 | 修改侧栏与搜索里显示的标题 |
| 还原 | 丢弃本页未保存的改动 |
| 保存修改 | 写入本地草稿（不联网） |
| 退出编辑 | 回到阅读态（草稿保留） |

## 本地草稿

草稿保存在 `localStorage["easydocument:drafts"]`：

- 刷新页面、切换文档、关闭浏览器都不丢
- 多个标签页之间自动同步
- 每条草稿记录路径、类型（新增/修改/删除）、内容、保存时间

提交栏的统计会实时反映：

```text
3 项本地草稿   [新增 1] [修改 1] [删除 1]
```

点击统计或把鼠标移到提交栏上，会展开草稿清单，可逐条放弃。

### 草稿在页面上的体现

- 侧栏中对应条目带「新增 / 修改 / 删除」角标
- 有草稿的文档，进入编辑时会直接加载草稿内容
- 标记删除的文档，阅读时会显示「此文档已标记为待删除」提示

## 一键提交

点击提交栏的 **一键提交**：

1. 未连接 GitHub 时，先弹出 Token 输入框
2. 可选填写提交信息（默认 `docs: 网页端编辑`）
3. 逐个文件写入或删除内容分支
4. 成功后清空本地草稿，并提示下一步

提交时的并发保护：

- 每次写入前读取远端文件的最新 `sha`
- 他人已修改过同一文件时，GitHub 会拒绝并返回冲突，界面提示刷新后重试，不会静默覆盖

提交信息示例：

```text
docs: 网页端编辑

更新 使用指南/目录结构.md
新增 使用指南/新章节.md
删除 参考/过时文档.md
```

## 重建站点

内容进了仓库，线上还不一定变。需要触发构建：

1. 打开 `/admin` → **构建部署**
2. 点 **立即重建**
3. 页面会轮询运行状态，显示「进行中 / 成功」与 Actions 链接

> [NOTE] 重建按钮在有未提交草稿时会禁用，避免误以为草稿也一起发布了。

也可以命令行触发：

```bash
gh workflow run deploy.yml --ref main
```

## 侧栏管理

编辑模式下侧栏提供：

| 操作 | 方式 |
| --- | --- |
| 筛选目录 | 顶部筛选框 |
| 全部展开 / 折叠 | 两个图标按钮 |
| 新建文档 | `+` 按钮（就地输入文件名） |
| 新建文档 / 文件夹 | 目录右键菜单 |
| 重命名 | 双击条目，或右键 → 重命名（只改显示名） |
| **拖拽排序** | 直接拖动条目到目标位置 |
| 删除 | 右键 → 删除 |
| 复制链接 / Markdown 链接 | 右键菜单 |

重命名、排序与删除同样先进入本地草稿，不会立即改动仓库：

- 重命名与排序写进该版本的 `path.json`，**不改物理文件名**
- 删除会把文件标记为待删除，提交时执行 `DELETE`

> [TIP] 顶部提交栏会把目录配置也计入统计（`[目录 1]`），
> 一次「一键提交」就把正文与目录结构一起推上去。

> [TIP] 没有索引页的目录在侧栏中不可点击（只作分组），因此不会出现点进 404 的情况。

## 正文右键菜单

在文档正文右键：

| 位置 | 菜单项 |
| --- | --- |
| 普通正文 | 复制本页链接、复制为 Markdown 链接、复制本文大纲、编辑此页 |
| 链接 | 新标签打开、复制链接、复制为 Markdown 链接 |
| 标题 | 复制该标题的锚点链接、复制为 Markdown 链接 |

选中文字时保留浏览器原生菜单（复制、搜索等）。

## 控制台

`/admin` 包含五个标签页：

| 标签 | 内容 |
| --- | --- |
| 总览 | 文档数、版本数、待提交数；快捷操作；内容来源（仓库 / 分支 / 配置路径） |
| 文档管理 | 按版本列出全部文档，新建、删除、跳转 |
| 目录与排序 | 调整显示名与顺序、隐藏条目、添加外部文档挂载、直接编辑 `path.json` |
| 站点配置 | 表单或源码编辑 `config.js`，保存前校验 |
| 构建部署 | 触发重建、查看最近一次运行 |

## 凭据与权限

使用 **fine-grained PAT**，权限最小化：

| 权限 | 用途 |
| --- | --- |
| Contents: Read and write | 读写内容分支的文件 |
| Actions: Read and write | 触发工作流、查询运行状态 |

存储方式：

- 不勾选「记住本设备」→ `sessionStorage`，关闭标签页即失效
- 勾选 → `localStorage`，可随时点「断开」清除

> [WARNING] Token 只存在于浏览器，不会进入构建产物或仓库。公用设备上不要勾选「记住本设备」，用完点「断开」。

## 常见疑问

**问：保存后换了一台电脑还能看到草稿吗？**
不能。草稿是本浏览器的，未提交就不会同步。要跨设备，必须前进到「提交」。

**问：提交了但线上没变？**
正常，还需要「重建站点」。这是有意设计，避免每次保存都触发一次部署。

**问：提交失败提示冲突怎么办？**
说明同一文件被别人改过。刷新页面重新编辑，或到 GitHub 上手动合并。

**问：能撤回已提交的修改吗？**
可以在 GitHub 上 revert 对应提交，然后重新触发重建。网页端编辑不提供「撤销提交」。
