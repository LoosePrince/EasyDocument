# 站点信息

```js
site: {
  name: "EasyDocument",
  title: "EasyDocument · 静态文档系统",
  description: "内容与代码分离的静态文档系统…",
  keywords: "文档,静态网站,Markdown,SSG",
  base_url: "/"
}
```

| 字段 | 作用 | 用在哪 |
| --- | --- | --- |
| `name` | 站点名称 | 顶栏 Logo 旁、版权默认值、面包屑 |
| `title` | 页面标题 | 浏览器标签页、`<title>`、Open Graph |
| `description` | 站点描述 | `<meta name="description">`、OG |
| `keywords` | 关键词 | `<meta name="keywords">` |
| `base_url` | 基础路径 | 所有站内链接与静态资源前缀 |

## base_url 怎么填

| 部署位置 | 值 | 示例访问地址 |
| --- | --- | --- |
| 域名根 / 用户 Pages | `/` | `https://example.com/docs-zh-CN/main` |
| 子目录 | `/子目录` | `https://example.com/docs-site/docs-zh-CN/main` |

规则：

- 以 `/` 开头，**不要**以 `/` 结尾
- 会自动归一：`docs`、`/docs/`、`//docs//` 都会变成 `/docs`
- 部署到 GitHub Pages 项目站点（`owner.github.io/repo/`）时通常不需要改，工作流会按实际情况处理

> [IMPORTANT] `base_url` 只影响链接前缀，不改变内容目录结构。改了之后需要重新构建。

## 首页标题与站点标题的区别

- `site.title` 是默认标题，首页会用它
- 每篇文档的标题由文档自身的 `#` 标题决定，形如 `文档标题 · 版本标签`
